## 職務要約

Windows Server／VMware環境の運用保守と、Linux・AWS環境での障害一次対応を経験。ログ・設定値・変更履歴を用いた切り分け、関係部署へのエスカレーション、手順書整備に従事してきました。個人開発ではAWS上に職務経歴サイトを構築し、GitHub Actionsによるデプロイ自動化、pytest・Motoによる単体テスト、Terraformによるコード化を実施。運用経験を基盤に、AWS環境の構築・運用改善へ担当領域を広げたいと考えています。

## 活かせる経験

- 障害切り分け：ログ・設定値・変更履歴・稼働状況を確認し、調査結果を整理。

- 情報連携・手順書：事象・影響範囲・確認済み事項を共有し、対応手順を文書化。

- AWS個人開発：配信・API・データ保存の構築、デプロイ自動化、単体テスト、Terraformによるコード化。

## AWS個人開発｜Cloud Resume Challenge

運用で接するAWSサービスを自分で構築し、設定・実装・デプロイ・テストまで経験することを目的とした個人プロジェクトです。生成AIを学習支援として活用し、自分で構築・操作を行いました。

| 項目 | 内容 |
| --- | --- |
| 構成 | ブラウザ → CloudFront → OAC → S3（非公開）<br>ブラウザ → API Gateway → Lambda（Python）→ DynamoDB |
| 本人担当 | AWS配信・API・権限設定、カウンター実装、日英ページ作成、GitHub Actions設定、単体テスト、Terraformによるコード化 |
| 設計上の工夫 | マネージドサービスでサーバー管理を軽減。DynamoDBの原子的な加算を採用。カウンター取得失敗時も職務経歴の本文を表示。 |
| 自動化・検証 | GitHub Actionsでフロントエンドを配信し、テスト成功後にLambdaを更新。pytest・Motoで応答、初回値、連続加算、保存結果の4項目を確認。 |
| IaC（Terraform） | コンソールで作成済みのバックエンド（API Gateway・Lambda・DynamoDB・IAM）をimportし、planで差分ゼロを確認。その過程でLambda実行ロールの過剰な権限に気づき、最小権限の専用ロールに置き換え。 |

今後の課題：監視・通知の整備、S3・CloudFrontのTerraform化。単体テストはモックでの検証であり、実AWSの設定検証とは区別しています。
